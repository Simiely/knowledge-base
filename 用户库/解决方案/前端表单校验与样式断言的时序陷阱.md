# 前端两个"看着对、程序不对"的时序陷阱：required 拦截 submit、transition 期间读样式

**TL;DR**：① 给表单加 `required` 会让浏览器在 **submit 事件派发之前**拦截空值，自定义校验弹窗永远不出现 —— 想自己控制校验就必须 `novalidate` + 手写校验；② `transition: all` 的元素，改样式后**立即**读 `getComputedStyle` 拿到的是过渡起始值，断言必须等过渡结束。

## 问题

- 表单加了 `required`，点提交没有任何自定义提示，弹出的是浏览器原生气泡；`onsubmit` 里的 `showDialog` 根本不执行。
- 给按钮加 `.active` 类后立刻读 `getComputedStyle(btn).color`，得到旧值；甚至直接写 inline `style.color='red'` 也不生效，看起来像"CSS 没匹配上"。

## 根因

1. **约束校验在前**：浏览器的表单约束校验（`required` / `pattern` / `min`）发生在 submit 事件**之前**，校验不过就不派发事件。所以"自己写校验 + 声明式必填"是冲突的，不是失效。
2. **过渡期计算样式**：有 `transition` 时，属性变更后有一段时间处于动画中间态，`getComputedStyle` 返回的是**当前帧的值**（即起始值）。inline 样式同样会被过渡覆盖观感。

## 解决

```html
<form novalidate onsubmit="return validate()">   <!-- required 可留作语义标记，但不参与原生校验 -->
```

```js
// 校验顺序按优先级手写，每步各自提示
if (!name.value.trim()) return showDialog("请填写名称");
if (!location.value)     return showDialog("请选择位置");
```

```js
// 断言前等过渡结束（过渡 0.12s → 等 250ms 足够）
btn.classList.add("active");
await sleep(250);
const color = getComputedStyle(btn).color;
```

## 预防

- **先决定校验归属**：要么全交给浏览器（原生气泡，样式不可控），要么全自己写（`novalidate`）。混用必踩。
- 有 `transition` 的元素，**任何计算样式断言都要等**：测试脚本固定 `sleep(≥2×duration)`；排查顺序「先查 transition，再怀疑级联/优先级」。
- 这两类问题的共同特征：**没有报错、没有异常、只是结果不对**。所以前端验证必须"读真实状态"（DOM + computedStyle）而不是"看截图顺眼"。
