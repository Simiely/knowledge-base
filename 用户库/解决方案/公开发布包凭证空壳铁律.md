# 公开发布包必须凭证空壳（zip 资产铁律）

**TL;DR**：任何要公开发布（GitHub Release / 网盘 / 对外分发）的打包资产，内部凭证文件（密码 / token / WebDAV 凭据）必须**空壳化**——只留字段骨架、不留真实值；真实凭证让用户下载后手动填。发布前检查每个打包产物，别让"本地能跑"变成"公开泄露"。

## 问题
workbuddy-credits-tool 的 v1.4.60 Release 资产 zip 里，`wb-sync.json` 含**明文 WebDAV 密码**，随 Release 公开可下载。

## 根因
打包脚本 `pack-platform.mjs` 直接打包本地工作目录——本地配置是带真实凭证的（本地能跑），于是原样进了公开 zip。典型"本地能用 = 发布安全"的误判。

## 解决
1. **发布产物空壳化**：打包时用空壳 `wb-sync.json`（字段在、值为空），真实凭证用户下载后手动填
2. **部署说明动态标注**：打包产物标注"请手动填写 WebDAV"提示，引导用户补全
3. **发布规范落字**：CHANGELOG / README 发布规范明确「公开 zip 必须空壳」铁律，Checklist 检查项
4. **事后处置**：旧 Release 资产已替换为空壳干净包；删除历史含密资产（或至少替换最新版）

## 预防
1. **发布前 Checklist 必有"凭证扫描"**：搜打包产物里的 `password` / `token` / 私钥 / 本地路径，逐项确认空壳
2. **打包与运行目录分离**：打包脚本从"模板目录"组装，不直接打包本地配置；或打包时显式剔除凭据文件（gitignore 同款清单）
3. **构建产物 CI 化**：若走 CI，配置从 Secret 注入，产物天然不含本地凭据
4. 对已有资产：**发现即替换**，并检查旧版本是否也被下载过（必要时考虑轮换泄露的密码）
