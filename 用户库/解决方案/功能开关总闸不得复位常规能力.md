# 开发者 / 实验功能总闸：kill switch 不得越权复位常规能力

**TL;DR**：「关闭开发者模式」只应复位诊断与 opt-in 实验项；若顺手把前台服务、保活、通知等常规能力一起关掉，用户关掉一个调试开关就会丢掉主功能。更隐蔽的是：开关状态与「服务是否真的在跑」不是一回事，靠开关推断会让兜底任务也一起停摆。

## 问题
关掉开发者总开关后，解锁手机不再自动刷新桌面组件；开启「自启动」也无效，用户看到的是「功能莫名失效」。

## 根因（三环叠加）
1. **kill switch 越权**：关总开关时执行了 `applyDevFlag("bgShot", false)`，把常规区「常驻通知」的 `shot_service_enabled` 清掉并停掉前台服务
2. **接收器随服务死**：解锁广播 `ACTION_USER_PRESENT` 只在服务 `onCreate` 里动态注册；它不在 Android 8.0 隐式广播豁免清单里，不能靠 Manifest 静态注册兜底
3. **假状态骗过兜底**：`ScreenshotWorker` 只读 `isShotServiceEnabled` 就「让位给服务」，但进程已被系统杀掉，结果两边都不截图，桌面停在旧图

## 解决
1. kill switch 用**白名单**：只复位日志、调试信息、悬浮窗、兼容通道等纯诊断 / 实验项；常规能力走独立 Prefs key，不进 dev flag 体系
2. 常规能力**移出门后区**：设置页单独「后台刷新」组（常驻通知 / 开机恢复 / 被清理后自动拉起），默认开、始终可见可改
3. 新增 `ShotServiceState` **查真实运行服务**，App 自愈与 Worker 让位共用同一判定；服务不在时 Worker 兜底截图
4. 关闭常驻通知的提示文案如实写「解锁自动刷新与下面两项一并失效」，不要写「不受影响」

## 预防
- feature flag 把「部署」与「曝光」解耦、提供一键回退；总闸的作用域必须先枚举再实现
- 渐进披露的硬规则：**收起一个区域不能藏掉唯一的状态入口**，默认生效的能力不该放在「关掉就整组隐藏」的门后
- 开关状态 ≠ 运行时状态；任何「让位 / 跳过」判断都要查实际进程，不要读配置就下结论
