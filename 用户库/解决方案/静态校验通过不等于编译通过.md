# 静态校验全绿 ≠ 编译通过

**TL;DR**：不依赖工具链的静态检查能守住结构与契约，但覆盖不了类型检查、符号解析、资源合并与链接。把它当 PR 快速反馈，真实编译必须始终留在 CI 里，且报告要写清「未覆盖」清单。

## 问题
本地无 SDK / 无 JDK / 依赖源被拦时，用脚本校验 XML、资源引用、旧 id、括号平衡，13 项全绿并据此判断「可以发版」，结果第一次真实编译就报错。

## 根因
静态校验读的是文本与正则，编译器读的是类型与符号。一次实测：新增 `ShotServiceState` 里 Kotlin 表达式体函数误写 `return`，静态校验 13/13 照常通过，`gradle assembleRelease` 才挂；修复后 CI 才绿。

## 解决
1. **报告自带边界**：显式列「已覆盖」与「未覆盖」（Kotlin 类型检查 / 符号解析、AGP 资源合并、aapt2 链接、R8、真机运行），并在正文写明「不等价于编译通过」
2. **CI 保留真实构建**：`gradle test` + `assembleRelease` 不可被静态校验替代，缺工具链时交由 runner 完成
3. **生成物加漂移门禁**：报告由脚本产出时，CI 跑完生成器接 `git diff --exit-code -- <报告路径>`，手改或过期一律红
4. **校验器自身也要能被正对照验证**：故意注错能报红，避免「永远通过」的假门禁

## 预防
- 校验项增加时同步更新 docstring、报告「已覆盖」行与执行状态页，别让数字漂移
- 「PASS」只统计 ERROR、WARN 不计入判定时，长期挂 WARN 等于规则失效
- 发版结论以真实构建产物为准，静态报告只作辅助证据
