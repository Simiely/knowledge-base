# 托盘常驻程序的可靠生命周期设计

**TL;DR**：托盘常驻程序的退出路径不可靠（杀进程/崩溃/断电都会跳过清理）——设置变更必须**即时持久化**、启动时做**状态修复**，不能依赖"退出时保存"；`FormClosing` 必须检查 `CloseReason` 区分用户关闭/系统关机。

## 问题
程序被任务管理器强杀后重启，之前监控的窗口仍处于半透明状态（WS_EX_LAYERED 残留）；设置改完崩溃就全丢；勾选"最小化到托盘"后 Windows 关机被阻止。

## 根因
1. **退出不可靠**：`Quit()` 中的恢复逻辑依赖正常退出流程（FormClosed → 遍历目标 → 清理），强制结束进程不执行
2. **保存不及时**：多个设置项只在关闭程序时才写 JSON，进程崩溃/强杀全部丢失
3. **关闭语义混淆**：`OnFormClosing` 无条件 `e.Cancel = true; Hide()`，把系统关机（CloseReason.WindowsShutDown）也拦截了

## 解决
1. **设置即时持久化**：每个值变更回调直接 `_settings.Save()`（透明度/开关/自启/托盘全部即时写盘）
2. **启动时状态修复**：启动遍历配置中所有目标，`SetWindowLong` 去掉残留 WS_EX_LAYERED + `RedrawWindow` 强制刷新（比 SetLayeredWindowAttributes 组合更可靠）
3. **区分 CloseReason**：只有 `CloseReason.UserClosing && _settings.MinimizeToTray` 才 `e.Cancel=true; Hide()`；系统关机放行
4. **资源释放顺序**：`_appIcon.Dispose()` 必须在 `_tray.Visible=false` 之后（NotifyIcon 对 Icon 的引用持续到自身清理完成）；Quit 挂 FormClosed 保证无论哪种退出都触发

## 预防
- 托盘程序：默认"启动时修复状态"而非"退出时清理状态"
- 设置类数据永远即时写盘，别等退出
- FormClosing 处理先看 CloseReason 再决定行为
