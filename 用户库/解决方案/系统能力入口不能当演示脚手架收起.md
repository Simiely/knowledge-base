# 系统能力入口不能当演示脚手架收起

**TL;DR**：调用真实系统 API、且是新用户必经路径的按钮（如 App 内「添加小组件到桌面」）不是演示控件。按「低频」把它收进隐藏层会造成可用性回归；删/收之前先分清「只在设计稿里模拟的脚手架」与「真实系统能力入口」。

## 问题
一轮「默认界面只留用户任务」的复审，把 App 内一键添加桌面小组件的按钮判为演示按钮收进隐藏兼容层。功能代码（系统 pin 请求、配置页、绑定逻辑）全部保留，但新三 Tab 界面没有绑定入口，用户装完 App 只能自己去桌面长按找组件。https 与 http 都正常，唯独「第一步」走不通。

## 根因
1. **分类判错**：看外观像演示（一个按钮 + 一句提示），没看它是否调真实 API。Android 8.0（API 26）起官方支持 `requestPinAppWidget`，本项目 `minSdk 26` 正好够
2. **低频 ≠ 用不到**：一键添加只在首次装 App 用一次，但它是必经路径，不是可选装饰
3. **渐进披露越界**：入口被放进「关掉就整组隐藏」的兼容层后，用户既看不到也改不了；收起一个区域不能藏掉唯一的状态入口
4. **复审清单把结论写死**：设计稿里一句「删 App 内添加小组件演示按钮」长期没人复核，错误判定随文档一起沉淀

## 解决
1. 抽单一入口 helper（`requestPin(context, dashboardId?)`），旧绑定与两个新入口共用，删掉重复实现
2. 设置页给**独立主按钮**（通用添加），列表卡片给**第 4 个按钮**（按该看板预选），两者语义不同但共用实现
3. 预绑定走一次性 pending（带 TTL），由系统拉起的配置页消费；不依赖部分 ROM 不触发的 success 回调
4. 不支持一键添加的 ROM 给手动引导并保留 pending，手动添加后配置页仍自动预选
5. 同步更正设计稿的错误判定，并在项目 DEVELOPMENT 记一坑一篇

## 预防
- 删/收任何入口前先问三句：它调真实 API 吗？新用户必经吗？删掉后有没有等价可达路径？三句有一句是「是」就别收
- 复审清单里「删 / 收」的结论要写明依据，别只写动作；语义真假靠人审，机器查不到
- 系统能力入口的降级方案（手动引导）与能力本身一起保留，不要只留成功路径
- 发版后按真实用户路径走一遍：安装 → 添加 → 配置 → 看到画面
