# 家庭提醒的推送通道选型（局域网 HTTP 是最强约束）

**TL;DR**：**Web Push 依赖 Service Worker，而 Service Worker 依赖安全上下文（HTTPS 或 localhost）** —— 局域网 HTTP 部署下这条路直接不通，"已经实现了"也只是在电脑 localhost 上能用。家庭场景优先 **iCalendar 订阅（WebDAV 放到日历里）+ 企微/Server酱 兜底**，都不要推送资质。

## 决策前提：先看有没有 HTTPS

| 部署形态 | Web Push | 说明 |
| --- | --- | --- |
| 局域网 HTTP（`http://192.168.x.x`） | ❌ 不可用 | 无安全上下文，SW 不注册；`localhost` 例外，所以本机测一切正常，换手机就失效 |
| 局域网 + 自签 HTTPS | ⚠️ 勉强 | iOS 需手动信任根证书，家庭成员每人装一次，不现实 |
| 域名 + 公网/隧道 HTTPS（如 Tailscale、反代 + Let's Encrypt） | ✅ 可用 | 才值得考虑 Web Push |

> 这是最容易误判的一条：**开发机上永远成功，家人手机上永远收不到**。

## 四条通道对比

| 方案 | 机制 | 能否离线/关页 | 前置 | 复杂度 |
| --- | --- | --- | --- | --- |
| **iCalendar 订阅**（推荐家用） | 服务端只写 `.ics` 或 CalDAV，手机系统日历订阅后自己提醒 | ✅ 系统日历常驻 | 无（不需 App、不需推送资质） | ⭐ |
| **企业微信群机器人** | Webhook 发群消息 | ❌ 需群 + 网络 | 建群、拿 Webhook | ⭐ |
| **企业微信自建应用** | 官方 API 发应用消息 | ❌ | 需公网 IP 白名单 | ⭐⭐⭐ |
| **第三方推送**（Server酱等） | 转发到微信/APP | ❌ | 注册、key 入库（凭证管理） | ⭐ |
| **Web Push** | VAPID + Service Worker | 关页后仍可（浏览器进程在） | **必须 HTTPS** | ⭐⭐ |
| **自家 App 轮询** | WorkManager/后台任务定时拉 API → 本地通知 | ✅ | 得先有 App + 后台保活权限 | ⭐⭐⭐ |

## 结论（可复用的判断句）

1. **没有 HTTPS，就不要设计依赖 Service Worker 的功能**（推送、离线缓存、PWA 安装一起废掉）。
2. **家用提醒的最优解不是"推送"，是"订阅"**：把提醒写进 `.ics` / CalDAV，由系统日历负责弹通知 —— 零资质、零常驻进程、跨安卓/iOS/鸿蒙。
3. 需要"立刻知道"的场景再叠一条 IM 机器人（企微群/Server酱），把它当**兜底**而不是主通道。

## 实现注意

- **VAPID 私钥不能塞 `.env`**：`python-dotenv` 不支持多行值，PEM 会被截断 —— 存成独立 JSON 文件（如 `data/vapid.json`，程序自生成）或 base64 单行。
- **事件 UID 必须带类型后缀**：同一物品可能同时有"过期"和"归还"两条提醒，固定 UID 会互相覆盖（`item-{uuid}-expiry@` / `item-{uuid}-due@`）。
- **外部写入失败要留痕可重试**（outbox 表），否则出现"数据库改了、日历没改"的僵尸状态。
