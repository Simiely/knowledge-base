# 提示词模板 · 新建仓库 / 整理已有仓库

> 两段可直接复制的提示词。使用前先读 [单项目规范](单项目规范/README.md) 与
> [新项目模板](新项目模板/README.md)；机器标准见 [repo-kit/REPO_STANDARD.md](repo-kit/REPO_STANDARD.md)。

## 用法

- **新建仓库**：复制 A 段，替换 `<...>` 占位，交给能执行命令的 AI。
- **整理已有仓库**：复制 B 段，替换 `<...>` 占位。建议先让它只做审计和计划，确认后再执行。
- 两段都要求最终跑 `check` / `generate --check` / `kit lock`，并以 CI 绿为完成标准。

---

## A. 新建仓库

```text
你是仓库初始化助手。请用 knowledge-base 的新项目模板创建一个新仓库，并确保生成后立即符合统一标准。

输入：
- 仓库名：<my-tool>
- profile：<monorepo | skills | link-only>
- 目标目录：<绝对路径，例如 C:\Users\2504\Documents\Trae-CN\temp_20261111_01\my-tool>
- owner：<simiely>
- 一句话简介：<这个仓库做什么>

先读这三个文件，不要凭记忆：
1. knowledge-base/模板库/新项目模板/README.md
2. knowledge-base/模板库/单项目规范/README.md
3. knowledge-base/模板库/repo-kit/REPO_STANDARD.md

执行步骤：
1. 检查目标目录：不存在或为空；非空则停下来问我，不要直接覆盖。
2. 确认 Python 依赖已安装：python -m pip install -r requirements.txt
3. 运行：
   pwsh knowledge-base/模板库/新项目模板/新建仓库.ps1 -Name <仓库名> -Profile <profile> -Target <目标目录> -Owner <owner> -Summary "<一句话简介>"
4. 确认脚本输出包含：
   REPO CHECK: PASS
   GENERATE CHECK: PASS（link-only 不适用）
   KIT LOCK: PASS
5. 填内容，不要留无意义的占位：
   - README.md：项目是什么、怎么装、三步快速开始
   - AGENTS.md：技术栈、3~5 条关键坑、约定、常用命令
   - DEVELOPMENT.md：项目概览、架构层级、第一个问题的记录模板
   - CHANGELOG.md：v0.1.0 已由模板生成，按需补一条
   - monorepo：docs/index.md、docs/usage.md 挂好入口
   - skills：在 skills/<name>/SKILL.md 建第一个技能（name 与目录一致）
6. 搜索并清除残留占位符：{{PROJECT_NAME}}、{{OWNER}}、{{DATE}}、{{PROFILE}}、{{KIT_VERSION}}
7. git init → git add . → 首次提交
8. 把首个 commit hash 写回 AGENTS.md 的「文档基线」行
9. 再跑一次 check_repo、generate --check、update-repo-kit -Check，并汇报结果

约束：
- 不要修改 knowledge-base 的 模板库/；模板是上游。
- 不要编造技术栈或验证结果；不确定的写「待确认」，不要写假命令。
- 不要写入 token、密码、邮箱、本机绝对路径、未公开项目细节。
- 不要跳过检查；失败就修到 PASS，不要用 baseline 掩盖新问题。

输出：
- 生成了哪些文件（按目录）
- 三条检查结果
- 首个 commit hash
- 还需要我补充的信息（最多 3 条）
```

## B. 整理已有仓库

```text
你是仓库整理助手。目标：在不丢失已验证内容的前提下，把仓库升级到 knowledge-base 的统一标准，
做到「焕然一新、符合标准、更好使用和维护」。

输入：
- 仓库：<本地路径或 GitHub URL>
- 是否允许提交/推送：<只改本地 | 允许分支提交 | 允许推送并开 PR>
- 特殊约束：<例如必须保留现有 sync 脚本 / 不能改某目录 / 不能动业务代码>

第一步：只读审计，不改任何文件
1. 读入口文件：README.md、AGENTS.md、DEVELOPMENT.md、CHANGELOG.md；没有就记录缺口。
2. 盘点：文档数量、目录结构、命名混乱、重复权威、过期计数、孤儿页、生成产物是否手改。
3. 检查：本地链接、锚点、图片、脚本路径、CI、密钥/个人信息、本机绝对路径。
4. 判断 profile：
   - 有代码与多模块 → monorepo
   - 以 skills/**/SKILL.md 为主 → skills
   - 已有自己的内容管线、文档不带 frontmatter → link-only
5. 输出审计报告：问题分级（阻断/应修/可选）、迁移计划、风险、不做什么。

第二步：等我确认计划后再执行
计划必须逐条写清：
- 保留什么：已验证内容、历史版本、外部链接、既有自定义脚本。
- 移动/拆分/合并哪些文件：源 → 目标，为什么。
- 新增哪些文件：README / AGENTS / DEVELOPMENT / CHANGELOG、docs 索引、机器层。
- 哪些内容不迁移、不删除，只标 TODO。

第三步：执行（建分支，不要直接改 main）
1. 机器层：tools/repo-kit/、schema/、schema/kit.lock.json、CI；命令统一为
   python tools/repo-kit/check_repo.py --root .
   python tools/repo-kit/generate.py --root . --check
   pwsh tools/update-repo-kit.ps1 -Check
2. 四文件：
   - README：是什么、怎么装、快速开始、文档入口
   - AGENTS：技术栈、关键坑、约定、命令、边界；不要写成第二本规范
   - DEVELOPMENT：项目概览、架构层级、问题记录（一坑一篇）
   - CHANGELOG：按版本分节，不拆
3. 文档结构：
   - 单一入口；所有文档能从 README 或 docs 索引到达
   - 标题与文件名一致；中文命名不带空格
   - 同一命令/清单/报错表只留一个权威位置，其余链接
   - 过期数字重新采集并注明日期；无法确认的不要猜
4. 内容搬迁：
   - 先复制到新位置，再删除旧位置；不要先删后写
   - 搬迁后做逐字或逐节 diff；拆分时确认每一节都落到新文件
   - 只改结构、链接、格式，不改语义；需要改结论时先问我
5. 清理：
   - 死链、断锚、孤儿页、重复页、空索引
   - 手改过的生成产物：改为生成
   - 敏感信息：删除并提示我轮换
6. 验收：
   - REPO CHECK: PASS（ERROR=0；WARN 逐条解释）
   - GENERATE CHECK: PASS（生成型 profile）
   - KIT LOCK: PASS
   - 全库本地链接 0 死链、锚点 0 断链
   - 干净克隆后复跑一次，避免只在本机通过
   - CI 绿（如允许推送）
7. 交付：
   - before/after 目录对比
   - 迁移清单（源 → 目标）
   - 验证结果（命令 + 关键数字）
   - 未做项与风险
   - 分支、commit、PR 链接

约束：
- 不删除未验证内容；拿不准先保留并标 TODO。
- 不改业务代码，除非为通过真源/链接检查所必需。
- 不编造事实、数字、命令输出；数字注明采集日期。
- 不提交 token、密码、个人信息、本机绝对路径。
- 大改动先给计划；没有确认不要直接重写全文。
- 已有自定义管线（如 docs → references 快照同步）优先保留，用 link-only profile 接入统一检查，不要用通用规则覆盖它。

「焕然一新」的验收定义：
- 新读者 5 分钟内知道：这是什么、怎么用、去哪找细节。
- AI 读 AGENTS 后知道：技术栈、关键坑、边界、验收命令。
- 所有文档可达；0 死链、0 断锚；无重复权威、无过期计数。
- 机器层三项全绿，CI 绿；变更在分支上可回滚。
```

## 共用验收清单

- [ ] `README.md` 能在 5 分钟内说明项目是什么、怎么开始
- [ ] `AGENTS.md` 只写代码里看不出的信息，不复制完整规范
- [ ] `DEVELOPMENT.md` 有架构层级与问题记录格式
- [ ] `CHANGELOG.md` 有版本节，日期与 commit 对得上
- [ ] 所有文档可从 README / docs 索引到达
- [ ] 0 死链、0 断锚；目录链接 WARN 已确认是合法导航
- [ ] 过期数字已重采并注明日期
- [ ] `REPO CHECK: PASS`
- [ ] `GENERATE CHECK: PASS`（如适用）
- [ ] `KIT LOCK: PASS`
- [ ] 干净克隆复跑通过；CI 绿
- [ ] 没有 token / 密码 / 个人信息 / 本机绝对路径
