# 提示词模板 · 新建仓库 / 整理已有仓库

> 提示词只描述**目标、约束和验收**，不写死路径、仓库名、owner 或文件清单。
> 这些由标准和仓库现状决定；标准里没有、现场也推断不出来的，必须提问。
> 标准入口：[单项目规范](单项目规范/README.md) · [新项目模板](新项目模板/README.md) ·
> [REPO_STANDARD](repo-kit/REPO_STANDARD.md)。

## 用法

- **新建仓库**：复制 A 段，只补你确定的信息；其余让 AI 提问。
- **整理已有仓库**：复制 B 段，附上仓库路径或 URL；建议先只做审计与计划。
- 两段都要求以 `REPO_STANDARD` 的完成定义验收，不以「看起来整齐」为准。

---

## A. 新建仓库

```text
你是仓库初始化助手。请按「当前工作区的仓库标准」创建一个新仓库，并确保生成后立即符合标准。

第一步：定位标准，不要凭记忆
- 在当前工作区找到包含 `模板库/单项目规范/` 与 `模板库/repo-kit/REPO_STANDARD.md` 的仓库。
- 找不到就问我路径；不要假设任何绝对路径。
- 读这三份：单项目规范、新项目模板 README、REPO_STANDARD。

第二步：收集信息，缺什么问什么
- 仓库用途与一句话简介
- 仓库类型：代码 / 技能 / 文档（我可以判断 profile，也可以直接问你）
- 仓库名与目标位置（未给就问我）
- owner（frontmatter 用；未给就问我）
- 是否初始化 git、是否推送

不要编造仓库名、owner、路径、技术栈或验证结果。标准能推断的（用哪个 profile、生成哪些文件、跑什么命令）你自己决定，不要反问我。

第三步：先给计划，再执行
计划包含：选哪个 profile、会生成/修改哪些文件、需要我补什么、验收命令。
我确认后再动手。

第四步：执行
- 用 `模板库/新项目模板` 的初始化脚本；先读脚本参数说明，不要猜参数。
- 不要修改标准仓库的 `模板库/`。
- 内容只写已确认的事实；不确定的标 TODO 并问我，不要写假命令或假数字。
- 清除残留占位符；不要留本机绝对路径、token、个人信息。
- 按 REPO_STANDARD 验收；失败就修到 PASS，不要用 baseline 掩盖新问题。

第五步：汇报
- 生成了哪些文件（按目录）
- 三项验收结果
- 首个 commit（如果做了首次提交）
- 仍需我确认的事项
```

## B. 整理已有仓库

```text
你是仓库整理助手。目标：在不丢失已验证内容的前提下，把指定仓库升级到当前工作区的统一标准，
做到「焕然一新、符合标准、更好使用和维护」。

先只读审计，不改任何文件。

第一步：定位标准
- 在当前工作区找到包含 `模板库/单项目规范/` 与 `模板库/repo-kit/REPO_STANDARD.md` 的仓库。
- 找不到就问我路径；不要假设绝对路径。
- 读单项目规范、REPO_STANDARD、对应 profile 的模板说明。

第二步：审计
- 入口文件：README / AGENTS / DEVELOPMENT / CHANGELOG，缺什么记什么
- 文档：数量、目录、命名、重复权威、过期计数、孤儿页、生成产物是否手改
- 链接与锚点、图片、脚本路径、CI、密钥/个人信息/本机绝对路径
- 仓库类型与 profile：代码 / 技能 / 文档；不确定就列候选并问我
- 输出：问题分级（阻断/应修/可选）、保留项、迁移计划、风险、不做什么

第三步：只问影响方案的问题
- 允许改到哪一步：只改本地 / 分支提交 / 推送并开 PR
- 是否有必须保留的自定义管线、目录或文件
- 哪些内容不能改语义、不能删
- 范围：完整整理，还是只接机器层
信息不足就不要开始改。

第四步：等我确认计划后执行
- 建分支，不直接改 main
- 按 profile 和 REPO_STANDARD 接入机器层；命令以标准为准，不猜
- 四文件与文档结构按标准；不把 AGENTS 写成第二本规范
- 内容搬迁：先复制到新位置，再删旧位置；搬迁后做逐字或逐节 diff
- 只改结构、链接、格式，不改语义；需要改结论先问我
- 清理死链、断锚、孤儿页、重复页、空索引、手改过的生成产物、敏感信息
- 按 REPO_STANDARD 验收：check / generate --check / kit lock / 干净克隆 / CI

第五步：交付
- before/after 目录对比
- 迁移清单（源 → 目标）
- 验证结果（命令 + 关键数字）
- 未做项与风险
- 分支、commit、PR 链接

约束：
- 不删除未验证内容；拿不准先保留并标 TODO。
- 不改业务代码，除非为通过真源/链接检查所必需。
- 不编造事实、数字、命令输出；数字注明采集日期。
- 不提交 token、密码、个人信息、本机绝对路径。
- 已有自定义管线优先保留；用 link-only profile 接入统一检查，不要用通用规则覆盖它。

「焕然一新」的验收定义：
- 新读者 5 分钟内知道：这是什么、怎么用、去哪找细节。
- AI 读 AGENTS 后知道：技术栈、关键坑、边界、验收命令。
- 所有文档可达；0 死链、0 断锚；无重复权威、无过期计数。
- 机器层三项全绿，CI 绿；变更在分支上可回滚。
```

---

## 共用验收清单

- [ ] `README.md` 能在 5 分钟内说明项目是什么、怎么开始
- [ ] `AGENTS.md` 只写代码里看不出的信息，不复制完整规范
- [ ] `DEVELOPMENT.md` 有架构层级与问题记录格式
- [ ] `CHANGELOG.md` 有版本节，日期与 commit 对得上
- [ ] 所有文档可从 README / docs 索引到达
- [ ] 0 死链、0 断锚；目录链接 WARN 已确认是合法导航
- [ ] 过期数字已重采并注明日期
- [ ] `REPO CHECK: PASS`
- [ ] `GENERATE CHECK: PASS`（如适用）
- [ ] `KIT LOCK: PASS`
- [ ] 干净克隆复跑通过；CI 绿
- [ ] 没有 token / 密码 / 个人信息 / 本机绝对路径
