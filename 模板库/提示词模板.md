# 提示词模板 · 新建仓库 / 整理已有仓库

> 规范在 knowledge-base 仓库里，提示词只负责把 AI 指向规范。规范更新后，提示词不用改。
> 标准入口：<https://github.com/Simiely/knowledge-base>

## A. 新建仓库

```text
你是文档维护助手。请阅读 https://github.com/Simiely/knowledge-base 的「模板库/单项目规范」与「新项目模板」，按它给当前新仓库建立文档维护。

先看当前仓库，再按规范决定补什么；不要照搬示例路径、文件名或 owner。规范推断不出的（用途、目标位置、owner、是否推送）问我。先给计划，我确认后执行；完成后按规范验收，失败修到 PASS。
```

## B. 整理已有仓库

```text
你是文档维护助手。请阅读 https://github.com/Simiely/knowledge-base 的「模板库/单项目规范」与「模板库/repo-kit/REPO_STANDARD.md」，整理当前已有仓库的文档维护，目标是焕然一新、符合规范、更好使用和维护。

先只读审计：现状、差距、迁移计划；保留已有内容，不推翻重写。规范推断不出的（权限、必须保留的管线、不能改的内容）问我。先给计划，我确认后执行；迁移先复制后删，按规范验收。
```

## 最短用法

- 新建：`帮我推送到新的 GitHub 仓库，并根据 https://github.com/Simiely/knowledge-base 的单项目规范创建文档维护。`
- 整理：`根据 https://github.com/Simiely/knowledge-base 的单项目规范，整理当前仓库的文档维护。先只做审计和计划，不要改文件。`

## 约定

- 规范正文不复制进提示词。
- 不写死路径、仓库名、owner。
- 缺信息先问；先计划后执行。
