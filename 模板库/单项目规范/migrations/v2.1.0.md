# v2.1.0 迁移说明

从 v2.0.0 升级。**不新增概念，只让既有条款真正生效**，无字段删除、无默认行为变更。

## 影响范围

| 变化 | 影响谁 | 是否必须做 |
|---|---|---|
| `LINK_DIR` 不再报 WARN | 所有仓库 | 否，重装 kit 即生效（只减少输出） |
| 模板 CI 加 `fetch-depth: 0` + PR 的 `--changed-since` | 新仓库自动；存量需手改 CI | **建议做**，否则 `co_change` 永不触发 |
| `monorepo` 的 `include` / `entry_files` 补 `DEVELOPMENT.md` | 新仓库自动；存量需改 taxonomy | 建议做，否则四件套之一不被检查 |
| `REPO_STANDARD` 1.5 增加 WARN 判定口径 | 人读 | 否 |

## 步骤

1. 重装 kit（会按新文件哈希重写 `schema/kit.lock.json`）：

   ```powershell
   pwsh tools/update-repo-kit.ps1 -Source <知识库>/模板库/repo-kit -Profile <profile>
   pwsh tools/update-repo-kit.ps1 -Check
   ```

2. 把 `DEVELOPMENT.md` 纳入扫描（`schema/taxonomy.json`，仓库自有文件，安装器不覆盖）：

   ```json
   "include": ["README.md", "AGENTS.md", "DEVELOPMENT.md", "docs/**"],
   "entry_files": ["README.md", "DEVELOPMENT.md"]
   ```

   放进 `entry_files` 而不是 `exempt_basenames`：门面文件不要求 frontmatter，
   但**链接仍要检查**——这正是本次修订的目的。

3. CI 补两处（`.github/workflows/repo-check.yml`）：

   ```yaml
   - uses: actions/checkout@v4
     with:
       fetch-depth: 0
   ...
   - name: Truth co-change
     if: github.event_name == 'pull_request'
     run: python tools/repo-kit/check_repo.py --root . --changed-since "origin/${{ github.base_ref }}"
   ```

4. 跑三项检查，允许出现「新增的断链」——那说明 `DEVELOPMENT.md` 里原本就有断链，只是没人看过。

## 验收

- `python tools/repo-kit/check_repo.py --root .` → `PASS`，且 `WARN` 数**下降**（`LINK_DIR` 消失）
- `pwsh tools/update-repo-kit.ps1 -Check` → `KIT LOCK: PASS (v2.5.0, spec=2.1.0, ...)`
- PR 里能看到 `Truth co-change` 这一步真的执行（不是 skipped）

## 不做第二步会怎样

行为与 2.0.0 完全一致：`DEVELOPMENT.md` 仍不被扫描，四件套阈值仍不生效。
`kit.lock.json` 里写的是 `spec_version: 2.1.0`，但实际覆盖面是 2.0.0 的——
**`spec_version` 只声明「按哪版规范整理」，不保证每一项都做了**。这也是本版
没有把 `DEVELOPMENT.md` 的纳入做成强制检查的原因：强制会让 11 个已接入仓库
在同一天全红，而它们的 README/CHANGELOG 本来就没打算改。
