# 初始化说明 · 复制模板库骨架

> 把 `模板库/` 变成**你自己的经验库骨架**，3 分钟完成。
> 适用于：开第二个经验库 / 给别人提供经验库模板。

---

## 一、复制模板库（3 选 1）

**方式 1：复制本仓库（推荐）**
直接 Fork 或复制整个 `knowledge-base` 仓库 → 清空 `用户库/`（删除数据，保留 `模板库/`）→ 得到一个新骨架库。

**方式 2：只复制 `模板库/` 目录**
```bash
cp -r 模板库 my-knowledge-base-template
cd my-knowledge-base-template
# 此时它就是一套完整骨架（规范/模板/索引空壳/归档说明），可作为新仓库根目录
```

**方式 3：纯本地**
直接复制目录，`git init` 重新开始，不推送 GitHub 也可（Obsidian 直接打开即用）。

---

## 二、改名与清理（2 分钟）

1. **删除示例条目**（如不需要）：`rm 模板/示例条目-工具类.md`，并把 `模板/索引.md` 里对应行删掉
2. **根 README**：改为你自己的库名（如 `# my-knowledge-base · 个人经验库`）
3. **README 顶部链接**：`初始化说明.md` 一节可删掉或保留（不影响使用）

---

## 三、开始积累（日常流程）

1. 踩坑解决后 → 复制 `模板/条目模板与使用说明.md` → 改中文命名 → 填内容
2. 放入用户库对应分类目录（`解决方案/` / `复用模式/` / `速查表/`）
3. 对应分类 `索引.md` 加一行（条目 | 摘要 | 标签 | 日期）
4. 你的用户库 README「最近更新」加一行
5. 推送

> 其余规则（命名、归档、隐私红线）见模板库 README「维护规则」，照做即可。

---

## 四、可选：仓库盘点表（断点续传）

> 管理多个项目仓库时，建议在用户库根目录加一个 `仓库盘点表.md`，记录所有仓库的文档规范状态 + 基线 commit，支持「断点续传」。规则见 [`单项目规范/README.md`](./单项目规范/README.md) 第九节。

```markdown
# 仓库盘点表 · 断点索引
| 仓库 | 领域 | 四件套 | 重写日期 | 基线 commit |
|---|---|---|---|---|
| (示例) my-project | Node | ✅ | 2026-08-08 | abc1234 |
```

---

## 五、本仓库内的迭代方式（同仓库双目录）

`knowledge-base` 仓库内已内置双目录：

- **改骨架** → 只动 `模板库/`（规范、模板、索引空壳）
- **沉淀数据** → 只动 `用户库/`（经验条目、索引行、盘点表、最近更新）

两者在同一仓库，互相可见、互不干扰；一个 commit 可同时包含骨架更新与数据更新。**数据永不回流模板库**——这是两库关系的铁律。
