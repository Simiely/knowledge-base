# 小程序云缓存：三层缓存 + 只刷当天

**TL;DR**：小程序云数据冷启动别用纯内存缓存（进程重启即失）；用「内存→Storage→云端」三层 + 每次打开**只增量刷当天**，云读取从"每次打开全量"降到"每次打开仅当天"，接近零配额消耗。

## 问题
每次完全退出再打开小程序，三个页面 `onShow` 都重新全量分页拉云端 → 云数据库读取次数（及头像 `getTempFileURL` 云存储调用）随打开次数线性增长，接近"云函数调取次数过多"。

## 根因
- `store.js` 缓存是**纯内存**对象，冷启动即清空；每页 `onShow` 各自触发全量分页 → 每次打开都重新拉
- 头像 `getTempFileURL` 未走缓存 → 每次冷启动重新请求云存储
- 云数据库 count()+Promise.all 并行分页兼容性有雷（count 过滤失效返回 0 → 静默空数据）

## 解决（三层缓存 + 增量刷新）
- **三层缓存**：内存 → Storage（`wx.setStorageSync` 持久化，重启仍在）→ 云端。云端拉取后写 `potty_cache_<env>_all`（`{ts, data}`），读取顺序内存→Storage（命中即返回，零云调用）→云端
- **只刷当天**：每次打开仅增量查 `timestamp >= 今天0点`（`getRecordsToday`）merge 进全量缓存，历史全部命中缓存；同会话 30s 冷却防切 tab 狂刷
- **写操作分级**：add 只刷当天、update/delete 全量重拉（编辑即时生效）、clear 置空落盘；下拉刷新仍 forceRefresh 全量
- **头像批量 + 缓存**：`toTempUrlBatch` 一次转多个 + 90 分钟 TTL 内存缓存 + 落 Storage 跨冷启动复用
- **容量守卫**：序列化 >900KB 不持久化，回退云端直读（避免 1MB/key 配额报错）

## 预防
- 小程序缓存别只用内存——冷启动即失，跨冷启动必须靠 `wx.setStorageSync`
- "当天在记、历史不变"场景用「只刷当天」比整桶 TTL 更贴合，云读取降一个量级
- `count()` 并行分页有兼容雷，稳定优先于微优化（数据量 <1000 用顺序分页开销可忽略）
