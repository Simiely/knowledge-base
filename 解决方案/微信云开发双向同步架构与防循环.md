# 微信云开发双向同步架构与防循环

**TL;DR**：云库 → 外部（腾讯文档）用**数据库触发器**实时出（增删改全覆盖）；外部 → 云库用**定时轮询 + 手动**（外部无 webhook 只能轮询入）。**防循环同步用源标记**：回写云库时打 `_syncSource: 'docs'`，正向同步检测到即跳过。ID 映射用映射表（`{docId, recordId}`），删除时靠它反查。

## 双向同步架构

```
[小程序] ↔ [云开发数据库 items]（主数据源）
                │ 数据库触发器（INSERT/UPDATE/REMOVE）
                ↓
          [云函数 syncToDocs] → [腾讯文档智能表]
                ↑
          [云函数 syncFromDocs]（定时 5 分钟 + 手动）← [腾讯文档智能表]
```

- **正向**：数据库触发器近实时（注意：触发器配置用 `INSERT/UPDATE/REMOVE`，运行时 `event.opType` 返回 `CREATE/UPDATE/DELETE`）
- **反向**：腾讯文档无原生变更 webhook → 只能轮询（固有延迟 = 轮询间隔）

## 防循环同步（最重要）

`syncToDocs` 写外部后，若 `syncFromDocs` 把变更又写回云库，云库一变又触发正向 → 死循环/无谓回写。

```js
// syncFromDocs 回写云库时打源标记
const docData = { ...fields, _syncSource: 'docs' };

// syncToDocs 开头拦截
if (event.doc && event.doc._syncSource === 'docs') {
  return { skipped: true };
}
```

## 关键细节

- **Token 管理**：OAuth token 存云数据库，读时检查 `expireAt`，过期前 1 分钟自动用 refresh_token 刷新并写回
- **recordId 映射**：云库 `_id` 与外部 `recordId` 无天然关联，用 `mapping` 集合记录；**删除时 `event.doc` 可能为空，必须用 `event.docId` 查 mapping 再删外部记录**
- **触发器事件**：CREATE 时字段在 `event.doc`、ID 在 `event.docId`；REMOVE 时 `event.doc` 可能为空，务必用 `event.docId`

## 预防

- 涉及双写/双向同步一律先画数据流图，标出"哪些写会触发哪些读"
- 回写源标记是防循环的最小成本方案，建议保留（即使外部无 webhook 不会真死循环，也能避免把"自己的同步写入"误判为对方改动）
