# 微信云开发同步变更检测优化（配额）

**TL;DR**：云开发数据库有**读写配额**（写 3 万/天、读 5 万/天），全量轮询同步会轻松撞线（写次数 ≈ 记录数 × 轮询次数/天）。两个优化：①**字段指纹变更检测**（`fp = 字段.join('|')` 存 mapping，没变就 skipped，只有真变化才写）；②**批量拉 mapping**（`db.command.in(recordIds)` 分批 100，把读次数从「记录数」降到「几条」）。

## 问题

- 每 5 分钟全量轮询 + 无条件 `update`：写次数 ≈ 记录数 × 288/天，逼近写 3 万/天上限
- 逐条 `where({recordId})`：读次数也推到 记录数 × 288/天，逼近读 5 万/天
- 撞线后超出的读写直接报错失败，同步中断

## 解决

```js
// 1. 变更检测（省写）：指纹比对，没变就跳过
const fp = [name, expireDate, count, category, note].join('|');
if (mapping.fp === fp) return { skipped: true };
// 否则才 update，并更新 mapping.fp

// 2. 批量拉 mapping（省读）：一次 in 查询拉回所有映射
const res = await db.collection('mapping')
  .where({ recordId: db.command.in(recordIds) })  // 分批 100
  .get();
```

**效果（100 条物品）**：

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 写次数/天 | ~28,800（逼近 3 万） | 仅变化记录（日常趋近 0） |
| 读次数/天 | ~28,800 | ~288 |

## 预防

- 任何定时轮询同步先算配额账：`记录数 × 次数/天` 对比配额，超了必须做变更检测
- 指纹比对是弱一致性（字段相等即视为未变），适合业务场景；需严格版本可改比对外部系统更新时间
- mapping 升级补 fp：无 fp 的记录视为需更新，首次同步正常写入一次
- 批量写操作注意第三方 API 频率限制，大批量走全量对账
